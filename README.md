# MergeWar

一个约十分钟一局的单人酒馆构筑游戏原型，用于验证“招募—构筑—自动战斗”循环是否足以驱动用户连续开局。

当前版本是玩法研究原型，暂时使用现行酒馆战棋资料降低规则验证成本；它不是可公开发行或商业化的产品版本。Cloudflare 预览地址只用于受控试玩和验收。

## 当前范围

- 三名当前酒馆英雄：诺兹多姆、雷诺·杰克逊和伊利丹·怒风；
- 亡灵 21 张、龙 22 张，覆盖当前数据快照中的两个完整种族和六个等级；
- 额外中立随从、衍生物和 7 张酒馆法术，用于支撑种族机制；
- 购买、出售、刷新、冻结、升本、三连和高一级发现；
- 嘲讽、圣盾、风怒、复生、烈毒、战吼、亡语、回合结束及战斗开始效果；
- 一名玩家和七名经营型电脑对手：各自保留金币、酒馆等级、升级费用、商店、手牌和阵容，并实际执行购买、出售、刷新、升本、三连与站位；
- 十回合上限、生命值、伤害和八人排名；
- 响应式操作页面与独立战斗页面，适配手机竖屏、手机横屏、桌面和刘海安全区，支持点击选牌、点击调整站位、鼠标和触摸拖动；
- 战斗回放支持攻击连线、交战高亮、浮动伤害、触发提示、暂停、1×/2×/4×速度和战后关键原因；
- 纯本地运行，不需要登录或服务器。

## 运行

项目没有运行时第三方依赖。进入目录后运行：

```bash
npm run dev
```

然后打开 <http://localhost:4173>。

也可以使用任意静态文件服务器，但不能直接双击 `index.html`，因为浏览器会限制本地 ES Module。

## 测试

```bash
npm test
npm run simulate
npm run build
```

`npm run simulate` 默认运行 300 局带种子的完整对局，用于检查崩溃、回合数、胜率与排名分布；`npm run build` 只把运行所需的静态文件写入 `dist/`。

## 素材来源与使用边界

- 名称、中文卡牌文本、属性和卡牌 ID 取自 2026-08-23 获取的 [HearthstoneJSON](https://hearthstonejson.com/) 最新 `zhCN/cards.json`；
- 页面通过 `art.hearthstonejson.com` 远程引用对应卡图，图片不保存在本仓库；
- 《炉石传说》及酒馆战棋相关名称、美术和游戏内容归 Blizzard Entertainment 所有；
- 当前版本只用于内部玩法研究和受控试玩，不应公开传播、商业化或提交微信小游戏审核；正式发行版需要替换名称、图片、文案、音频和足以构成实质性近似的表达。

当前原型故意不包含：

- 微信登录、分享和广告；
- 真人匹配、服务端同步及完整经营AI；
- 酒馆法术、饰品、任务、双打和完整赛季卡池；
- 炉石音频、特效、边框及客户端 UI 的逐像素复刻。

七个电脑对手使用与玩家相同的基础经济约束，并按流派、对子、卡牌强度和阵容位置做启发式决策。玩家参与的战斗使用完整战斗规则，电脑之间暂时仍使用战力估算；后者是当前主要简化，而不是直接生成阵容。

## 下一步验证

1. 让 5 至 10 名熟悉酒馆战棋的测试者每人完成至少三局；
2. 记录首局完成率、中位单局时长和立即重开率；
3. 验证熟悉酒馆战棋的玩家能否快速理解压缩后的六级卡池；
4. 检查经营型电脑的决策是否可信，并记录明显错误的购买、升本和站位；
5. 核心循环成立后，再接入微信小游戏平台层。
